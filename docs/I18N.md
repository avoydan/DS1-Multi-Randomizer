# Language and localization

Status labels: **AUTOMATED VERIFIED**, **STATICALLY VERIFIED**, **GAMEPLAY UNVERIFIED**, **PARTIAL**, **DEFERRED**, **UNSUPPORTED**.

The application is available in **English** (the canonical source and the fallback) and **Polish**. The language is a presentation setting only: **it never reaches a world.** It is not part of the Seed Code, the generation settings, the canonical configuration, any hash, the run manifest's package list or the identity of a history entry. The same Seed Code produces the same files in either language (AUTOMATED VERIFIED: the golden fixtures are unchanged and the code that derives seeds and settings does not reference the language; see the tests below).

## 1. What the person sees

* **Setting.** Header: *Language* with three choices: **Automatic**, **English**, **Polski** (no locale codes are shown). Changing it re-renders the whole interface at once, without a restart.
* **Resolution (main process, before the first render).** A saved explicit choice wins. *Automatic* walks Electron's preferred system languages (`app.getPreferredSystemLanguages()` plus `app.getLocale()`): the first one that is `pl*` gives Polish, `en*` English; anything unsupported (and an empty list) gives English. `electron/language.ts` (`resolveLanguage`), tested in `electron/language.test.mjs`.
* **No flash.** `main.tsx` asks the main process for the resolved language, initialises i18next and only then renders. The window background is already the app's.
* **Persistence.** `userData/settings.json` → `language` (`en` | `pl`; *Automatic* is stored as no value). `migrateSettings` keeps it and drops unknown values.
* **Native dialogs and startup errors** (folder picker title, save dialog title, "Desktop startup failed", backend start problems) are produced by the main process in the resolved language (`MAIN_MESSAGES` in `electron/language.ts`, parity tested).

## 2. Architecture

* **Library:** `i18next` 26 + `react-i18next` 17 (mature, nested keys, interpolation, plural rules including Polish `one/few/many/other`, runtime switching, fallback, TypeScript key typing). Resources are bundled with the renderer (no network, no files read at run time).
* **Resources:** `apps/desktop/src/locales/<language>/<area>.json`, one file per area: `common`, `app`, `settings`, `game`, `hints`, `history`, `seed`, `smoke`, `pool`, `plan`, `diagnostics`, `support`, `errors`. They are bundled as the groups of a single i18next namespace, so every key reads `area.path.to.text` and **keys are type-checked from the English files** (`i18n/i18next.d.ts`). `t('settings.items.worldItems.label')` is a compile-time-checked call.
* **English is canonical.** Polish is a full translation, not a demo: there are no `[PL]` markers (a test forbids them).
* **Terminology (Polish).** *Losuj świat* (Randomize), *Zastosuj do gry* (Apply to game), *Przywróć oryginalne pliki* (Restore original game), *Przywróć i utwórz nowy świat* (Restore and create shared world), *Wczytaj seed* (Load seed), *Kod seeda* (Seed Code), *Zaawansowane* (Advanced), *Historia losowań* (Run history), *Arkusz podpowiedzi* (Hint sheet), *Mało spoilerów / Progresja / Pełne spoilery*, *Uczciwy / Nieuczciwy / Bardzo nieuczciwy*, *Tryb wyścigu*. The wording follows the current product vocabulary.
* **Game content stays English.** Names of bosses, items, maps, NPCs and enemies are written as the game's English data writes them, in both languages (the app has no trustworthy Polish source for them). The design allows a later localized lookup: the hint sheet and the test worlds receive such names as parameters (`{{owner}}`, `{{former}}`, `{{replaced}}`), never inside translated sentences.
* **Fog "game language".** `fog.language` is a world setting in the Seed Code (the language of the *game's own text* in the generated files). It is **not** derived from the interface language. It is labelled *In-game text language* / *Język tekstów w grze* with an explanatory hint so it cannot be confused with the app's *Language*.

## 3. Backend text: codes, not sentences

* The backend still sends its English `message`/`userMessage` as a fallback and for the log, but always together with a **stable code**. The renderer translates by code: `errors.codes.<CODE>` (about 70 codes: generation, fog, key placement, world data, game state, activation/restore, Seed Code decoding, support bundle). The renderer never parses an English sentence.
* An **unknown code** shows a localized generic message (`errors.generic`, or `errors.genericWorld` for `FOG_*`/`WORLD_DATA_*`) and the original text/code as expandable **technical details** (`ErrorNotice`).
* Plan preview lines carry `labelKey`/`valueKey`/`params` next to their English text (`describePlanBehaviors`), translated from `plan.*`; item pools travel as ids (`worldItems,npcGifts`), not as a sentence. Backend test: every key it can produce exists in both languages and the English resource equals the backend sentence.
* History stores **semantic data** (the `generated | applied | restored` status enum, ISO times, Seed Codes); the labels and dates are produced at display time (`history.status.*`, `Intl.DateTimeFormat`).
* Quick/extended **test worlds** (40 scenarios): the contracts keep the English source; `apps/backend/scripts/smokeLocaleSync.mjs` generates the English resource from them (`--write`; the test fails when it is out of date) and Polish is written per scenario id. Targets and expectations of quick worlds are built from **structured expectations and templates** (`describeSmokeTargetWith`), asserted equal to the contracts' English sentences.

## 4. Formatting

Dates, times and numbers are formatted for the interface language (`i18n/format.ts`: `Intl.DateTimeFormat`/`NumberFormat` with `en-GB`/`pl-PL`), including the decimal comma in Polish. **Never** formatted or translated: Seed Codes, hashes, versions, ids, operation ids, file names, enum values in JSON/exports, percentages shown as `NN%`.

## 5. Completeness checks (AUTOMATED VERIFIED)

`apps/desktop/src/i18n/locales.test.mjs`:

* both languages provide the same areas and the same keys (plural forms counted as one key); Polish has no extra keys;
* English has `one/other`, Polish `one/few/many/other` for every plural;
* every `{{variable}}` of a text exists in its translation and vice versa;
* no empty values, no `[PL]/[EN]/[TODO]`, no Polish text that is an unchanged English sentence;
* English is the fallback: removing a key from Polish shows the English text, never the key;
* plural and interpolation behave (`1 slot`, `3 sloty`, `5 slotów`; Windows paths survive unescaped);
* every backend error code has both translations;
* an **untranslated-literal detector** over every `.tsx` screen: visible JSX text and `title/placeholder/aria-label/alt/label/hint` attributes must come from the resources.

More tests: `electron/language.test.mjs` (Auto/explicit/unsupported locale, persistence), `backend/src/core/smokeLocale.test.mjs`, `planBehaviors.test.mjs`, `diagnosticsText.test.mjs`, `hintSheet.test.mjs` (the texts of exports use real resources and fail on a missing key).

## 6. Layout and text expansion

Polish strings are on average 15–30 % longer than English. The layout was built for that: labels wrap, option rows use `justify-content: space-between` with flexible text, selects are full width, the header's language control is compact, dialogs scroll (`max-height`, `overflow-y: auto`) and no font was reduced. The packaged-app check (EN and PL, every screen) is recorded in `docs/IMPLEMENTATION_STATUS.md`.

## 7. Installer

`electron-builder.yml` → `nsis.installerLanguages: [en_US, pl_PL]`; `multiLanguageInstaller` is on by default (Unicode installer) and `displayLanguageSelector` stays off, so NSIS picks the language from the **Windows display language** (`GetUserDefaultUILanguage`): Polish Windows → Polish installer/uninstaller, anything else → English (the first language). The product name is not translated. Verified statically on the built installer (the Polish and English wizard strings are present) — **STATICALLY VERIFIED**; the wizard itself was not run under a Polish Windows UI (**GAMEPLAY UNVERIFIED** equivalent for the installer: needs a Polish Windows or a changed display language).

## 8. Not done / limits

* **PARTIAL (reduced in 0.33.0):** the problem lines of an invalid *preset* are translated for the sentences a person can meet (`problemText.ts` in the contracts maps 17 validator sentences to `errors.problems.*`; tested for both languages and their variables); any other validator sentence is still shown as the validator wrote it, under the localized lead, with the sentence always available as a tooltip.
* **PARTIAL:** `ENEMY_PLACEMENT_*`/world-data failures whose engine message is dynamic show the localized generic message plus the English text under *Technical details*.
* **Error codes:** 15 more backend codes got their own plain message in 0.33.0 (data tool, game data/catalog, output write, nothing enabled, fog component missing/crashed/timed out, merge conflict, ...); a test pins that every code in `userMessages.ts` is translated and that the English resource is the backend wording.
* **DEFERRED:** Polish names of game content; more languages (the structure supports adding `locales/<code>/` and a line in `electron/language.ts`).
